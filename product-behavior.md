# Product Behavior — Ledger (Portfolio Dashboard)

See also: [design.md](design.md), [schema-spec.md](schema-spec.md)

Local-first, single-user portfolio tracker. No live price feed — all values come from user-imported CSVs. No Watchlist/Alerts feature (out of scope; must never reappear — grep `watchlist` case-insensitive in `src/` must return nothing).

## Layout

Five views: **Budget**, **Accounts** (nav label "Positions"), **Register**, **Quotes**, and **Settings**. Accounts view, top to bottom: `Nav` → 2-column layout with an "All Accounts" card + collapsible category cards (left, 360px) and a flexible right panel holding the allocation chart, asset-class filter + "Import" button row, and the aggregate positions table (or the closed-positions table) — see "Accounts page" below. Register view: `Nav` → 2-column layout with a scope picker (left, 360px) and stats/chart/activity table (right) — see "Register" below. Budget view: `Nav` → single centered card — see "Budget" below. Settings view: `Nav` → centered settings card (max-width 560px).

**Default landing page**: Accounts. A fresh install opens there; thereafter the last-viewed view is persisted, so an app locked on Settings reopens on Settings. A backup written by an older build that recorded a now-retired view opens on Accounts rather than failing to render.

## Nav

Nav renders on every view. Logo mark (accent-filled square with a plus-icon SVG) + "Ledger" brand, followed by 4 always-visible div-based pills (not radio-input `.seg`), in order:

- **Budget** — the income/expense budget tracker. Active when `state.view === 'budget'`. First pill.
- **Positions** — the Accounts page. Active when `state.view === 'accounts'`.
- **Register** — the balance-history tracker. Active when `state.view === 'register'`.
- **Quotes** — read-only held-symbol price table. Active when `state.view === 'quotes'`.

Each pill shows a grid icon + label; clicking dispatches `SET_VIEW` for that pill's view. The active pill gets accent text color and background; inactive pills are muted with a hover highlight. Settings has no nav pill — it's reached only via the gear icon (below) and is not part of this 4-tab row even though `'settings'` is itself a `view` value.

- **Sync Now icon button** (refresh icon, `title="Sync now"`): always rendered; `disabled` whenever Drive is not connected or a sync/restore is in progress (`!connected || syncing`). Triggers a backup sync to Google Drive.
- **Settings gear** (SVG icon): navigates to the Settings page (resets `settingsSection` to "Backup" on every open).

## Allocation chart

Reusable `.card.blueprint.elev-sm` component taking `positions: Position[]` and `title: string` props. Renders a 2-column grid grouped by *effective* asset class (`assetClassManualOverride || assetClass`), computed via `allocationBars(positions)`. Each cell shows: class label + USD value inline (12px font), percentage right-aligned (muted), and a compact horizontal bar (height 6px, accent color fill) sized to percentage of total portfolio value.

- **Accounts page usage** — the only usage: called with selection-scoped positions (all accounts, a single account, or a single account's closed positions) and a title of `"Allocation — All Accounts"`, `"Allocation — {account.name}"`, or `"Allocation — {account.name} (Closed)"` per selection state.
- Empty positions list → empty grid with no crash.

## Transactions table

(Not rendered in any current view; kept for data-model and future-surface reasons.)

- Type filter tags (`All` + every distinct `Transaction.type` currently in state, alphabetical) + free-text search (symbol or date substring, case-insensitive).
- Always sorted by date descending — no user-controlled sort.
- Columns: Date (formatted `MMM D, YYYY`), Symbol, Type (colored tag: Buy=accent, Sell=outline, Dividend=neutral, anything else=neutral), Shares, Cost Basis, Amount Invested, Position Link.
- **Position Link**: shows an "UNMATCHED" outline tag (with a tooltip explaining "likely fully sold or removed") when the transaction's symbol has no corresponding open `Position`; otherwise shows plain "Linked" text. This is purely derived per render — no stored flag.

## Accounts page

2-column layout accessed via the "Positions" tab in the Nav. Left panel (360px fixed width) shows an "All Accounts" card followed by collapsible category cards; right panel (flexible) shows allocation chart, filter controls, and aggregate positions table.

- **"All Accounts" card** (always first, always visible): shows the sum of market value across ALL positions, unscoped by category/account/filters (`acctAllAccountsTotal`). Click dispatches `CLEAR_ACCOUNT_SELECTION`; highlighted when `state.selectedAccountId === null`.

**Left panel — Category cards** (Taxable / Non-Taxable / Tax-Deferred / Closed Positions order):
- **Card header** (click to toggle expanded state): category/collection label + account-count badge (`.tag.tag-neutral`, unfiltered count for category cards; for Closed Positions, badge is fixed at account count of those with ≥1 closed position).
- **Collapsed state** (default): shows only the header with badge.
- **Expanded state**: lists account rows, each clickable (cursor pointer), styled with:
  - Institution and account name on line 1 (or name only if institution is empty), using institution—name format.
  - Tags on line 2: for Taxable/Non-Taxable/Tax-Deferred cards, total value (formatted USD), account number, updated date (ISO format); for Closed Positions card, realized G/L sum (formatted USD, or `—` if all underlying closed positions have `realizedGLBasis === 'unknown'`), account number, updated date.
  - Click to select: dispatches `state.selectedAccountId` or toggles if already selected (toggle semantics). Global selection state persists across category expansions.
- **Closed Positions card** (4th card, always shown in the card list): visible only if ≥1 account in state has ≥1 closed position. Badge shows total count of such accounts. Expanded list shows only accounts with closed positions. Totals on line 2 are realized G/L sums per account.

**Right panel** (flexible width):
- **Allocation chart** — top: `AllocationChart` component with positions from current selection (all accounts, single account, or single account's closed positions) and title `"Allocation — All Accounts"`, `"Allocation — {account.name}"`, or `"Allocation — {account.name} (Closed)"`.
- **Filter row** — asset-class `.seg` radio control (computed from all positions, not selection-scoped, sorted alphabetically) + "Import" button. Free-text search field for symbol/name filtering. When Closed Positions + account is selected, asset-class filter and search are scoped to that account's closed positions only.
- **Aggregate Positions table** (open positions view; shown when a Taxable/Non-Taxable/Tax-Deferred category account is selected, or "All Accounts" is selected) — sorted by column selection (`state.sortKey`/`state.sortDir`, toggled via `TOGGLE_SORT`). **Columns**: Symbol, Asset Class, Shares, Avg Cost, Current Price, Amount Invested, Market Value, G/L, G/L %, **% of Selection** (percentage of selection total, not whole portfolio), Row-count badge. **% of Selection** reflects only positions in the current selection (account or all). Rows are **aggregate groups** — one row per unique grouping key (`trackingSymbol || symbol`, i.e. a position's tracking symbol takes precedence over its own symbol when set) + effective asset class; tax category and retirement status do not partition groups, so matching positions merge across accounts. Every group, including size-1, renders as one row. Groups aggregate shares, cost basis, and market value; price is derived as summed value / summed shares.
  - **Sorting**: clicking a sortable header (Symbol/Asset Class/Shares/Avg Cost/Current Price) toggles asc/desc via `TOGGLE_SORT`; clicking the active column flips direction, a different column resets to `asc`. An `↑`/`↓` arrow marks the active column. Sorting orders by aggregate/derived group values, computed client-side after grouping. Amount Invested/Market Value/G/L/G/L % are display-only, not sortable.
  - **Row click → overlay**: clicking any row (cursor pointer) opens `PositionGroupOverlay`, a dialog (`.dialog-backdrop`/`.dialog`, closable via Escape/backdrop-click/X button). Title: `` `Symbol — Name — Asset Class` ``, where the "Symbol" slot shows the group's Tracking Symbol instead of its own Symbol when one is set on the group. Lists the underlying positions sorted by account.institution, then account.name, falling back to account.accountNumber. **Overlay columns** (11): Account, Symbol, Tracking Symbol, Name, Shares, Avg Cost, Current Price, Market Value, % of Portfolio, Override, Delete. **Account display (two-line)**: line 1 institution—name (or name alone if no institution); line 2 muted tax-category and retirement labels (e.g. "Taxable • Retirement"). **Editable cells**: Account (dropdown listing all accounts; selecting dispatches `UPDATE_POSITION` with `patch: { accountId }`); Symbol and Name (`<input type="text">`, click-to-edit, empty/whitespace-only reverts silently, trimmed non-empty commits); Tracking Symbol (same input style, but empty is a valid commit — submitting blank clears an existing tracking symbol via `patch: { trackingSymbol: undefined }`, reverting the position to grouping/display by its own Symbol; a no-op submit that doesn't change the effective value dispatches nothing); Shares/AvgCost/Price (`<input type="number">`, click-to-edit; valid non-negative number commits, invalid/empty reverts silently, no error UI). All fields: Enter or blur commits, Escape reverts with no dispatch. % of Portfolio is display-only and uses the whole-portfolio total (every position), not the current selection. **Side effect**: editing Symbol, Tracking Symbol, or Account changes the position's group key, so its row disappears from the open overlay on the next render (the overlay stays open — a natural re-render consequence). **Delete column**: blank header, trash-icon button per row; prompts `window.confirm('Delete this position? It will be moved to Closed Positions.')`; on confirm dispatches `CLOSE_POSITION`, converting the position into a `ClosedPosition` (`realizedGL: null`, `realizedGLBasis: 'unknown'`, `closedDate` = today) rather than hard-deleting it. Override column contains the `AssetClassOverrideSelect` control.
- **Closed Positions table** (closed positions view; shown when Closed Positions card + account is selected) — **Columns**: Security (symbol + name), Closed (date, ISO format), Realized G/L (signed formatted USD, or `"unknown"` if `realizedGLBasis === 'unknown'`), Delete (trash-icon button per row, triggering confirm `"Delete this closed position? This permanently discards its realized G/L history."`, removing on confirm). Asset-class filter and symbol search apply. No `PositionGroupOverlay` interaction. Realized G/L is never a fabricated number — `"unknown"` is shown when the basis is unknown.
- **Empty state**: "No positions to show." when selection has no positions.

**Two-card overlap**: an account with both open and closed positions appears in two cards — one in its tax-category card (Taxable/Non-Taxable/Tax-Deferred) and one in the Closed Positions card. Selecting the account under one card sets `state.selectedAccountId` globally, but the visual selection highlight is scoped to the card it was selected from — the account does not highlight under the other card simultaneously. Switching to view the account's data (in the right panel) toggles between open-positions view (when selected from a tax-category card) and closed-positions view (when selected from Closed Positions card).

**No longer shown**: "Subtotal row", "Cash/Investment/Total" column split, 3-section (Taxable/Non-Taxable/Tax-Deferred) table layout, dividers between sections. **Account CRUD**: remains in CSV import flow only (new-account form at import time).

## Register

Accessed via the Nav's "Register" tab. A manually-recorded balance-history tracker, independent of imported Positions/Transactions — data comes only from user-entered `BalanceEntry` rows via the "Record Balances" dialog.

**Layout**: 2-column, left scope picker (360px) + right balance-history panel.

**Left panel — Scope picker**:
- **"All Accounts" card** (always first, always visible): shows the sum of every account's latest recorded balance (`registerAllAccountsTotal`). Click selects the "All Accounts" scope (`SET_REG_ACCOUNT` with `accountId: null`); highlighted when no account is selected.
- **Category cards** (one per tax category — Taxable/Non-Taxable/Tax-Deferred, via `registerCategoryCards`): header (click toggles expand via `TOGGLE_REG_CATEGORY_EXPANDED`) shows category label, account-count badge, and category total (sum of member accounts' latest balances). Expanded: one row per account showing institution—name, that account's latest balance, an "N entries" tag, and an "As of {date}" tag; empty categories show "No accounts in this category." Clicking an account row selects it (`SET_REG_ACCOUNT`) as the scope; selected row is highlighted.
- Scope selection is a single global `state.regAccountId` (not a toggle — clicking an already-selected row does not deselect; only clicking "All Accounts" or a different account changes scope). Category expand/collapse state is per-category (`state.regExpanded`), independent of scope selection.

**Right panel — Balance history** (scoped to the selected account, or every account when scope is "All Accounts"):
- **Title**: `"{institution} — {name}"` for a single account, or `"All Accounts — Balance History"`.
- **Stats strip** (4 cells, derived from the scoped ledger via `accountLedger`): Current balance (latest recorded balance, summed across scope accounts); Net change recorded (sum of period-over-period balance deltas, `null`/opening entries excluded); From activity (sum of each entry's `activities` amounts, each signed by `ACTIVITY_SIGN[type]`); Unexplained (Net change minus From activity, i.e. the portion of each balance change not attributed to a recorded activity type). Net change / From activity / Unexplained are signed (`+`/`-`) and colored gain/loss green/red by sign.
- **Balance-over-time chart**: SVG line+area chart plotting the scoped total balance at each recorded date (carrying forward each account's last-known balance between its own entries), with Y-axis USD gridline labels and up to 6 X-axis date-tick labels. Each point has a hover tooltip (`{date} — {balance}`). Single-point series render a centered flat line.
- **Activity filter**: `.seg` radio, `All` / `With Activity` (dispatches `SET_REG_ACTIVITY_FILTER`) — `With Activity` hides entries with zero `activities` (`activities.length === 0`).
- **"Record Balances" button**: opens the Record Balances dialog (below); dialog-open state is component-local.
- **Activity table** (newest-first, then by accountId; scoped + filtered via `scopeLedger`): Date, Account (name + institution), Balance, Change (`+`/`-` USD, or "Opening" for an account's first-ever entry), Attributed activity — stacks one tag per activity (type + signed amount + optional note), row grows to fit (no truncation); shows "Not attributed" only when `activities.length === 0`, Unexplained (signed USD, or `—` for an opening entry), Delete. Clicking a row (anywhere but the trash icon) opens the Edit Balance Entry dialog for that entry — see below.
- **Delete**: trash-icon button per row; `window.confirm('Delete this balance entry? This cannot be undone.')`, then dispatches `DELETE_BALANCE_ENTRY`.
- **Empty state**: "No balance entries recorded for this scope yet." when the filtered/scoped row list is empty.

**Record Balances dialog** (`RegisterBalanceDialog`): mode `.seg` — **Enter manually** (default) or **Copy-Paste**.
- **Manual mode**: an editable draft-row table (Date, Account select, Balance, one or more Activity entries, remove-row button), seeded with one blank row (account pre-filled from the current Register scope if one is selected, date pre-filled to today). "+ Add row" appends another blank row. Each activity, rendered as its own row beneath the balance row, has its own "+ Add activity" button to append another activity and a per-activity remove button — available in both add-mode and edit-mode rows.
- **Copy-Paste mode**: two paste zones (Headers, Values), parsed via the same `tableToCsv()` clipboard parser CSV import uses, then mapped to fields by header-hint matching (`BALANCE_FIELD_HINTS`: date/account/balance/activityType/activityAmount/note) — account values are fuzzy-matched to an existing `Account` by id/name/number/institution—name (`matchAccountId`), activity values matched by exact or prefix match against the 7 activity types (`matchActivityType`, defaulting to `None`), dates normalized to `YYYY-MM-DD` (`normalizeDateInput`). Pasting rebuilds the draft-row table from the parsed result; an inline error shows if either zone is empty or parsing yields no headers/rows.
- **Row validity**: a row is valid (`isDraftRowValid`) once it has a date, an account, and a numeric balance — activity fields are optional. Invalid required cells get a red border. Save is disabled at 0 valid rows; its label reads "Save N entries"/"Save 1 entry".
- **Commit**: Save normalizes each activity item on a row (`amount` = `Math.abs(parseFloat(amount)) || 0`; unmatched activity type falls back to `'None'`), converts valid draft rows to `BalanceEntry[]` (activity amounts non-negative — sign is derived at read time via `ACTIVITY_SIGN`) and dispatches `ADD_BALANCE_ENTRIES`, then closes and discards local draft state. Cancel/✕/backdrop-click closes without saving.
- **Replace semantics**: recording a new entry for an `(accountId, date)` pair that already has an existing entry **replaces** it — existing entries matching an incoming `(accountId, date)` key are dropped before the new entries are appended, so re-recording a date does not create a duplicate point. This dedup only applies against *pre-existing* entries: if a single save batch itself contains two draft rows with the same `(accountId, date)`, both are appended (not merged) — the UI doesn't prevent entering duplicate rows within one dialog session.

**Edit Balance Entry**: clicking a row in the Activity table (not its trash icon) opens `RegisterBalanceDialog` pre-filled with that entry's data — single draft row, no mode toggle (Copy-Paste unavailable) and no "+ Add row" (still supports "+ Add activity"/per-activity remove within the row). Primary button reads "Save changes" and dispatches an update to the existing entry (not `ADD_BALANCE_ENTRIES`). The dialog also offers a "Delete" action guarded by the same `window.confirm('Delete this balance entry? This cannot be undone.')` as the table's trash icon, closing the dialog immediately on confirm. Cancel discards all edits and closes without saving.

## Budget

Accessed via the Nav's "Budget" tab (first pill). Persisted data: `AppState.budgetIncomeByYear: Record<string, {monthly, yearly}>`/`budgetExpensesByYear: Record<string, Expense[]>`/`budgetTransactions: BudgetTransaction[]` — income and expenses are stored per calendar year (see "Year-scoped income & expenses" below). `categories`/`categoryMappings` are no longer part of `AppState` — the page receives them as `categories`/`categoryMappings` props sourced from a separate global (cross-portfolio) category store (see "Cross-Portfolio Categories" below). The `categories` prop is the source of truth for the category list (not derived from expense/transaction strings); every category `<select>` on the page is populated from it, plus a trailing "+ Add new category…" option (`window.prompt`, creates a new `Category` — dispatched via a separate `categoryDispatch`, not the page's main `dispatch`; invisible to the user). All other page state (period, filters, sort, form drafts, selected year, Spend records search/sort/pagination/cell-edit state) is component-local, not persisted.

- **Import auto-categorization**: imported rows (Copy-Paste CSV or Upload CSV/OFX/QFX) never carry a category column. Each row's category is resolved automatically: a case-insensitive substring match of the row's `description` against the global store's `categoryMappings[].substring` (latest-`updatedAt` mapping wins on multiple matches) sets the category; no match falls back to "Other". This resolution happens before dedup, so the resolved category participates in the dedup key.
- **Manual Add Record live-prefill**: as the user types into the Description field, the Category select live-prefills from the same mapping match against the typed text. Once the user manually picks a category themselves, further description edits stop overwriting it (manual pick always wins over the live-match).

- **Year-scoped income & expenses**: budgeted expenses and income are each stored per calendar year (`budgetExpensesByYear`/`budgetIncomeByYear`). Monthly mode always reads/writes the **current** calendar year's snapshot; Yearly mode reads/writes whichever year is selected via the Year dropdown. Selecting the Year dropdown to a year with no existing data, or editing income/an expense for such a year, **seeds it from the nearest existing year** (closest by absolute year distance; a tie favors the earlier year) — or starts empty if no year has data yet. On app load, if the current calendar year has no snapshot yet but an earlier year does, the most recent prior year's expenses and income are **auto-copied forward** ("rollover") as the new current year's starting point. This applies identically and independently to budgeted expenses and to income.
- **Period toggle** (`.seg`, Monthly/Yearly/Analytics, default Yearly, left-aligned) recomputes Income/Budgeted/Actual-spend/Variance/Category-Breakdown/Spend-records via `toPeriod`. Monthly always reflects the real current month (`new Date()`); Yearly is scoped by a page-level **Year** select (same row as the toggle, right-aligned to the page) that only appears in Yearly mode. Switching period resets Spend records to page 1.
- **Summary cards** (4): Income (click-to-edit via a pencil-icon button, pre-filled with the raw stored value for the current period; Enter commits, no Cancel — saving one period's income **zeroes the other period's** stored value, by design), Budgeted, Actual spend ({range label}), Variance (green when `Budgeted >= Actual`, else red). Categories with `excludeFromSpend` set have their transactions excluded from Actual spend and Variance (and from every other actual-spend-derived figure on the page — Expenses table Actual/Variance columns, Category Breakdown, and Analytics, see "Analytics" below); Budgeted is never affected by this flag.
- **Add/edit/delete expense**: "Add Expense" opens a modal (Name/Category/Amount/Frequency); invalid submit (blank name, or amount `<= 0`) silently no-ops. Existing rows use a pencil-icon button (`aria-label="Edit expense"`) for inline edit (Name/Frequency/Amount dispatch per-change; Category is staged and dispatched on "Done") and a trash-icon button (`aria-label="Delete expense"`) guarded by `window.confirm('Delete this expense? This cannot be undone.')`.
- **Expenses table sorting**: attached to the **Name/Category/Amount column headers** themselves (click to sort by that column; click the already-active column to reverse direction — a chevron shows current direction) — no separate "Sort by" dropdown. Default: Category ascending. A separate "Filter by category" select still exists alongside it. Table ends in a **Total** row (2px top-border delineator) summing Amount/Actual/Variance across the currently filtered/sorted rows (Actual/Variance summed per **distinct** category present, not per row, to avoid double-counting). A row whose category has `excludeFromSpend` set shows Actual as if it had no transactions (Budgeted column unaffected).
- **Category Breakdown panel**: bar-per-category from `categoryBreakdown(currentYearExpenses, periodFilteredTransactions, period)`, where `currentYearExpenses` is the full unfiltered `budgetExpensesByYear[year]` array for the active period's year, independent of the Expenses table's category filter. Bar width is relative to the largest category's total (so the largest category's bar is always 100%). Empty state (`currentYearExpenses` empty): "Add expenses to see the breakdown."
- **Spend records** card (rendered above the Expenses/Category-Breakdown grid): shares the page's `period`/`selectedYear` state — Monthly shows the current calendar month's `budgetTransactions`, Yearly shows the selected year's — the same underlying set (`periodFilteredTransactions`) as the "Actual spend" summary card. Columns: Date, Description, Category, **Account**, Amount. Account column shows `row.accountName` or `—` when unset. A "Show excluded" checkbox next to the search box (component-local `showExcludedRecords` state, default unchecked) hides rows whose category has `excludeFromSpend` set when unchecked; checking it reveals them. Toggling it resets pagination to page 1. This only controls row visibility in this table — it does not change the Actual-spend/Variance figures elsewhere, which always exclude those transactions regardless of this toggle.
  - **Search**: a text box (`aria-label="Search records"`, placeholder "Search records") does a case-insensitive substring match against Description, the resolved Category name, and Account name; applied before sort/pagination, and resets to page 1 on every keystroke. Empty search shows all period-filtered rows.
  - **Sorting**: all 5 columns (Date, Description, Category, Account, Amount) are sortable via column-header click, mirroring the Expenses table's pattern — a chevron (`SortIcon`) marks the active column/direction; clicking the active column reverses direction, clicking a different column switches to it (default direction ascending, except Date which defaults to descending when newly selected). Default sort on load: Date descending.
  - **Pagination**: active only when the period+search-filtered row count exceeds 500; page size 100; Prev/Next buttons + "Page X of Y" label, right-aligned below the table. Hidden entirely when the filtered set is 500 rows or fewer. The **Total** row always sums Amount across the full filtered set (search-filtered, not just the current page).
  - **Per-cell edit**: clicking any data cell (Date/Description/Category/Account/Amount) turns just that cell into an editable input in place (`<select>` for Category, `<input type="date">` for Date, `<input type="number">` for Amount, plain text otherwise) — no more whole-row pencil/Done affordance. Enter or blur commits a single-field `UPDATE_BUDGET_TRANSACTION` patch; Escape reverts without committing. Committing a Category change (via the `<select>`'s `onChange`, which fires immediately rather than waiting for blur) additionally upserts a `CategoryMapping` keyed by the row's exact `description` (dispatched via `categoryDispatch` to the global store, not the page's main `dispatch` — invisible plumbing detail); no other field's commit does this. Clearing the Account cell to blank unsets `accountName`.
  - **Delete**: trash-icon button per row (`aria-label="Delete record"`, `window.confirm('Delete "{description}"? This cannot be undone.')`), unchanged.
  - Manual "Add Record" inline form (Date/Description/Category/Amount — no Account field; manually-added records never get an `accountName`): shows an inline error ("Date is required."/"Amount must be greater than 0.") and does not dispatch if date is empty or amount `<= 0`; empty description falls back to the selected category. On successful add, a `CategoryMapping` is upserted (via `categoryDispatch`) keyed by the record's exact trimmed `description`, and `selectedYear` jumps to the added record's year (`recDate`'s year) so it's visible immediately in Yearly mode even if it falls outside the previously selected year. In Monthly mode there is no equivalent jump — an added record only appears if its date falls in the real current calendar month.
- **Import**: "Import transactions…" opens a modal with a required **Account name** text field (`aria-label="Import account name"`) above the tab switcher — the value is applied uniformly as `accountName` to every row of whichever tab's batch gets imported (not parsed per-row from file/paste content). Two mutually exclusive tabs:
  - **Copy-Paste tab**: CSV only — a textarea parsed by a non-RFC-4180 comma-split parser (`parseBudgetTransactionsCsv`).
  - **Upload file tab**: accepts CSV, OFX, and QFX files — dashed dropzone (click or drag-drop, `accept=".csv,.ofx,.qfx"`, `aria-label="CSV, OFX, or QFX file"`). The file's extension picks the parser (component-local state `importFileKind: 'csv' | 'ofx' | null`): `.csv` → `parseBudgetTransactionsCsv`, `.ofx`/`.qfx`/anything else → `parseOfxTransactions`. Two distinct inline errors show when the file parses to 0 transactions: `"No transactions found in file — check it has date/description/amount columns"` (CSV) or `"No transactions found in file — check it's a valid OFX/QFX export"` (OFX/QFX).
  - Both tabs dispatch `IMPORT_BUDGET_TRANSACTIONS`. **Import** button is disabled until Account name is non-empty, and — Upload tab only — also while an upload-tab inline parse error (CSV or OFX/QFX) is showing (i.e. also requires a file that parsed to ≥1 row).
  - Dedup key (`importBudgetTransactions`): `date|description|categoryId|amount|accountName` — category is resolved via mapping match (see auto-categorization above) before the dedup check runs, then checked against existing transactions and against earlier rows in the same import batch; duplicates silently dropped, no error shown. Including `accountName` means two otherwise-identical transactions differing only by account are no longer treated as duplicates. Status line shows `"{n} row(s) detected"` (pre-dedup parse count).
- **Empty states**: Expenses table (no rows after filter) — "No expenses to show."; Spend records table (no rows for selected period/search) — "No records for this period."; Import status before any import — "Never imported".

### Analytics

Third option on the Budget page's period toggle (Monthly/Yearly/**Analytics**). Selecting it hides the Year select, the 4 summary cards, the Expenses/Category-Breakdown grid, and the Spend records table, and renders `BudgetAnalytics` (read-only, no dispatch) in their place. The period toggle row itself (left-aligned tabs) stays visible in Analytics mode; only the Year select (Yearly-only) drops out of that row. Switching back to Monthly or Yearly restores all of the above unchanged.

- **Scope**: computed from ALL years present in `budgetTransactions` (not just the currently-selected Year), most-recent-year-first, soft-capped at 8 years.
- **Empty state**: if there are no budget transactions at all, every section shows "No records for this period." Otherwise, each section renders independently; four sections additionally require 2+ years of data and show their own "No records for this period." message when only 0 or 1 year exists: **Spend trend**, **Savings rate** (shrinking-trend stat), **Category trends year over year**, and **Biggest movers**. The other sections — **Over-budget count**, **Spike month**, **Concentration risk**, **Category share of spend**, **Monthly seasonality**, **Budget accuracy by year** — render normally with just 1 year of data.
- **Excluded categories**: categories with `excludeFromSpend` set are left out of every Analytics figure, identically to the rest of the Budget page (audited across all 7 sections).

Seven sections, in fixed order:
1. **Areas of concern** — up to 5 stat cards: Over budget (count of categories over budget this year + their names, or "None"), Spend trend (% change, colored by direction; 2+ years needed), Spike month (the standout high-spend month, with its total and a z-score-style detail; needs enough monthly history), Savings rate (current rate and whether it's trending up or down vs. the earliest year; 2+ years needed), Concentration risk (the single category taking the largest share of spend, highlighted red if it crosses the high-risk threshold).
2. **Savings rate by year** — a bar chart, one bar per year, labeled with each year's savings-rate percentage.
3. **Category share of spend over time** — a stacked horizontal bar per year (each segment = one category's share of that year's spend, colored, with a hover tooltip showing name + percentage) plus a color-keyed legend below.
4. **Monthly seasonality** — a bar chart of average spend per calendar month (Jan–Dec) across all years, with the peak month's bar highlighted in a different color.
5. **Budget accuracy by year** — one row per year showing a budget-vs-actual overlay bar plus an "Under by $X" / "Over by $X" variance label, colored by direction.
6. **Category trends year over year** — a table (Category, one column per year, YoY % change, "Over budget" pill), sorted by % change; needs 2+ years.
7. **Biggest movers** — two lists side by side, "Biggest increases" and "Biggest decreases," each showing up to 3 categories with their average-monthly-spend change (e.g. "+$120/mo"); needs 2+ years.

### Cross-Portfolio Categories

Categories and category mappings are shared across ALL portfolios opened in this browser, not scoped to a single portfolio — renaming a category (or editing/adding a mapping substring) in one portfolio's Settings changes what every other portfolio sees too, immediately.

**Seeding on upgrade**: the FIRST portfolio the user unlocks after upgrading to this feature has its existing categories and mappings copied verbatim (same ids, no dedup) into the new shared store; this happens once, automatically, invisibly — no prompt, no confirmation. Every OTHER portfolio's own pre-existing categories/mappings are left behind and never merged in: that portfolio's transactions/expenses will show as uncategorized ("Other"/blank) until the user manually recreates matching categories and re-categorizes them. Which portfolio ends up seeding the store is simply whichever one happens to be unlocked first after upgrading — not something the user can choose or control.

- **Auto-lock on inactivity**: the app also locks itself proactively, without a refresh or tab close. ## PWA install & offline behavior

- **Install prompt**: relies entirely on the browser's native install affordance — address bar icon on desktop Chrome/Edge, "Add to Home Screen" on Android/mobile browsers. No custom in-app install button or banner.
- **Offline behavior**: app shell (HTML/JS/CSS, icons, manifest) loads from cache when offline. IndexedDB-backed app data (accounts/positions/transactions) already works offline regardless of PWA status. Drive Connect sign-in and Drive sync (Sync button) require network — the gsi/client script and Drive API calls are intentionally NOT cached/proxied by the service worker, so they fail or hang when offline. This is expected, not a bug.
- **Update behavior**: silent auto-update (`registerType: 'autoUpdate'`). No "new version available" prompt. The next reload or navigation after a new deploy picks up the latest service worker and assets automatically.

## Formatting conventions

- USD: `fmtUSD(n)` → `"$1,234.56"` / `"-$1,234.56"` (no leading `+` on positives; callers that want a `+` prepend it themselves for G/L-style fields).
- Percent: `fmtPct(n)` → always signed, `"+1.20%"` / `"-1.20%"` / `"+0.00%"`.
- Shares: `toLocaleString('en-US', {minimumFractionDigits:2, maximumFractionDigits:2})`.
- Dates in Transactions table: `Date.toLocaleDateString('en-US', {month:'short', day:'numeric', year:'numeric'})` (e.g. "Jan 5, 2026"). Dates in Closed Positions "Closed" column are shown as raw ISO strings.
